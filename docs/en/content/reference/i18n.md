## In short

The kit speaks **English** (`en`) and **French** (`fr`). The project's `language` sets the language of the site,
of the page templates written by `doc-kit new`, of the section labels the build looks for, and of the command-line
messages. Every text comes from the kit's dictionaries, and a project can replace any of them with `texts`.

1. **Two dictionaries**, `i18n/en.json` and `i18n/fr.json`, with the same keys and the same variables (a test checks
   it), completed by fragments in `i18n/<language>/*.json`.
2. **Namespaces** say where a text is used: in the site at runtime, in the HTML template, in the Markdown
   extensions, in the callouts, on the home page, in the CLI.
3. **`texts`** in `doc.config.mjs` overrides any key, for this project only.

## The namespaces

| Namespace | Used by | Embedded in the site |
|---|---|---|
| `ui.*` | The site's script: menu, search, tour, footer, print | yes |
| `home.*` | The home page | yes |
| `template.*` | The HTML template: top bar, dialogs, search field | no (rendered at build) |
| `render.*` | The Markdown extensions: "Guided tour", "Enlarge", "Before", "After" | no (rendered at build) |
| `callouts.*` | The default titles of the callouts | no (rendered at build) |
| `cli.*` | The messages of the commands | no |

## Overriding texts

```js
texts: {
  "home.title": "Document a web app with {accent}",
  "home.titleAccent": "{product}",
  "home.primaryAction": "Start in five minutes",
  "callouts.note": "Good to know",
  "ui.feedback": "Tell us what is missing",
},
```

This site does exactly that: its home page title is a `texts` override. The keys most often changed:

| Key | Default (English) | Variables |
|---|---|---|
| `home.title` | Understand, use and {accent} | `{accent}`: the highlighted end, `home.titleAccent` |
| `home.titleAccent` | configure {product} | `{product}` |
| `home.primaryAction` | Start reading | `{section}`: the featured section |
| `home.eyebrow` | Official documentation · v{version} | `{version}` |
| `home.journeysTitle` | Recommended paths | |
| `ui.feedback` | Report a problem | |
| `ui.footer.site` | {product} v{version} · documentation generated on {date} · … | `{product}`, `{version}`, `{date}`, `{pages}`, `{captures}` |
| `callouts.tip` … `callouts.how` | Tip, Warning, Blocking error, Required permissions, Good to know, Recipe, How it works | |

- A variable that is not given stays visible as `{name}`: easy to spot and fix.
- A plural is an object, chosen with the language's plural rules:
  `"ui.subPages": { "one": "{n} sub-page", "other": "{n} sub-pages" }`.
- An unknown key is a build warning that suggests the closest one: `texts: unknown i18n key “home.primary” → closest
  key: home.primaryAction`.

## Writing in French

A French project (`language: "fr"`) uses the French section labels (`## À quoi ça sert`), the French templates and
messages. The Markdown extensions accept both spellings everywhere (`:::ecran`, `[!ASTUCE]`, `[[droit …]]`); see
[Extended Markdown](#/write/markdown). Findings use `R` instead of `N` for the "no effect" family.

## Pitfalls and observed gaps

> [!NOTE] Other languages
> Only `en` and `fr` are accepted by `language`. A third language needs its dictionary, its page templates, the
> labels of `standard/templates.json` and its standard: see `CONTRIBUTING.md` in the kit.

> [!NOTE] The CLI language outside a project
> Before a project exists, the messages are in English, or in the language of `--lang` or `DOC_KIT_LANG`.
