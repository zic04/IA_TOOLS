## En bref

Le kit parle **anglais** (`en`) et **français** (`fr`). La `language` du projet fixe la langue du site, des gabarits
de page écrits par `doc-kit new`, des libellés de section que cherche le build, et des messages de la ligne de
commande. Chaque texte vient des dictionnaires du kit, et un projet peut remplacer n'importe lequel avec `texts`.

1. **Deux dictionnaires**, `i18n/en.json` et `i18n/fr.json`, avec les mêmes clés et les mêmes variables (un test le
   vérifie), complétés par des fragments dans `i18n/<langue>/*.json`.
2. **Les espaces de noms** disent où un texte est utilisé : dans le site à l'exécution, dans le modèle HTML, dans
   les extensions du Markdown, dans les encadrés, sur la page d'accueil, dans la ligne de commande.
3. **`texts`**, dans `doc.config.mjs`, remplace n'importe quelle clé, pour ce projet seulement.

## Les espaces de noms

| Espace de noms | Utilisé par | Embarqué dans le site |
|---|---|---|
| `ui.*` | Le script du site : menu, recherche, visite guidée, pied de page, impression | oui |
| `home.*` | La page d'accueil | oui |
| `template.*` | Le modèle HTML : barre du haut, fenêtres de dialogue, champ de recherche | non (rendu au build) |
| `render.*` | Les extensions du Markdown : « Visite guidée », « Agrandir », « Avant », « Après » | non (rendu au build) |
| `callouts.*` | Les titres par défaut des encadrés | non (rendu au build) |
| `cli.*` | Les messages des commandes | non |

## Remplacer des textes

```js
texts: {
  "home.title": "Documentez vos applis avec {accent}",
  "home.titleAccent": "{product}",
  "home.primaryAction": "Démarrer en cinq minutes",
  "callouts.note": "Bon à savoir",
  "ui.feedback": "Dites-nous ce qui manque",
},
```

Ce site fait exactement cela : le titre de sa page d'accueil est un remplacement `texts`. Les clés les plus souvent
modifiées :

| Clé | Défaut (français) | Variables |
|---|---|---|
| `home.title` | Comprendre, utiliser et {accent} | `{accent}` : la fin mise en valeur, `home.titleAccent` |
| `home.titleAccent` | configurer {product} | `{product}` |
| `home.primaryAction` | Commencer la lecture | `{section}` : la section mise en avant |
| `home.eyebrow` | Documentation officielle · v{version} | `{version}` |
| `home.journeysTitle` | Parcours recommandés | |
| `ui.feedback` | Signaler un problème | |
| `ui.footer.site` | {product} v{version} · documentation générée le {date} · … | `{product}`, `{version}`, `{date}`, `{pages}`, `{captures}` |
| `callouts.tip` … `callouts.how` | Astuce, Attention, Erreur bloquante, Droits requis, À savoir, Recette, Comment ça marche | |

- Une variable qui n'est pas fournie reste visible sous la forme `{nom}` : facile à repérer et à corriger.
- Un pluriel est un objet, choisi selon les règles de pluriel de la langue :
  `"ui.subPages": { "one": "{n} sous-page", "other": "{n} sous-pages" }`.
- Une clé inconnue est un avertissement du build qui suggère la plus proche :
  `texts : clé i18n inconnue « home.primary » → clé proche : home.primaryAction`.

## Écrire en français

Un projet en français (`language: "fr"`) utilise les libellés de section français (`## À quoi ça sert`), les
gabarits et les messages français. Les extensions du Markdown acceptent partout les deux graphies (`:::ecran`,
`[!ASTUCE]`, `[[droit …]]`) ; voir [Le Markdown étendu](#/write/markdown). Les constats utilisent `R` au lieu de `N`
pour la famille « sans effet ».

## Pièges et écarts constatés

> [!NOTE] D'autres langues
> Seuls `en` et `fr` sont acceptés par `language`. Une troisième langue demande son dictionnaire, ses gabarits de
> page, les libellés de `standard/templates.json` et son standard : voir `CONTRIBUTING.md` dans le kit.

> [!NOTE] La langue de la ligne de commande hors d'un projet
> Tant qu'aucun projet n'existe, les messages sont en anglais, ou dans la langue de `--lang` ou de `DOC_KIT_LANG`.
